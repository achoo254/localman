- **Description:** Generate Better Auth schema, create `user_files` table for JSON blob storage, run migrations against PostgreSQL.

## Key Insights

- Better Auth CLI generates Drizzle schema: `user`, `session`, `account`, `verification` tables
- `user_files` is the only custom table — stores JSON blobs per user
- `content` column uses `jsonb` for flexibility; server never parses it
- `entity_type` column distinguishes collections from environments
- Composite unique index on `(user_id, filename)` prevents duplicates

## Requirements

### Functional
- Better Auth tables created via generated schema
- `user_files` table: id, user_id, filename, entity_type, content (jsonb), updated_at, created_at
- `entity_type` enum: `collection`, `environment`
- Unique constraint on `(user_id, filename)`
- Foreign key from `user_files.user_id` to `user.id` with CASCADE delete
- Drizzle migrations generated and applied

### Non-Functional
- All timestamps use `timestamptz` (timezone-aware)
- Indexes on `user_id` for fast per-user queries
- `updated_at` auto-updates on modification

## Architecture

### Database Schema

```
Better Auth (auto-generated):
┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────────┐
│   user   │  │ session  │  │ account  │  │ verification │
│──────────│  │──────────│  │──────────│  │──────────────│
│ id (PK)  │←─│ userId   │  │ userId   │  │ id (PK)      │
│ email    │  │ token    │  │ provider │  │ identifier   │
│ name     │  │ expiresAt│  │ accountId│  │ value        │
│ ...      │  │ ...      │  │ ...      │  │ expiresAt    │
└──────────┘  └──────────┘  └──────────┘  └──────────────┘

Custom:
┌────────────────────────────────────────┐
│            user_files                  │
│────────────────────────────────────────│
│ id          UUID PK DEFAULT gen_random │
│ user_id     TEXT NOT NULL FK→user.id   │
│ filename    VARCHAR(255) NOT NULL      │
│ entity_type VARCHAR(20) NOT NULL       │
│ content     JSONB NOT NULL             │
│ updated_at  TIMESTAMPTZ NOT NULL       │
│ created_at  TIMESTAMPTZ NOT NULL       │
│────────────────────────────────────────│
│ UNIQUE (user_id, filename)             │
│ INDEX  (user_id)                       │
│ INDEX  (user_id, entity_type)          │
└────────────────────────────────────────┘
```

### entity_type Values
- `collection` — Postman v2.1 JSON export of a collection + folders + requests
- `environment` — Environment variable set JSON

## Implementation Steps

### 1. Create PostgreSQL database

```bash
# On dev machine (assumes PostgreSQL installed)
createdb localman
# Or via psql:
psql -U postgres -c "CREATE DATABASE localman;"
psql -U postgres -c "CREATE USER localman WITH PASSWORD 'localman';"
psql -U postgres -c "GRANT ALL PRIVILEGES ON DATABASE localman TO localman;"
```

### 2. Generate Better Auth schema

```bash
cd backend
npx @better-auth/cli generate --output src/db/auth-schema.ts
```

This creates Drizzle table definitions for `user`, `session`, `account`, `verification`.

**Important:** Review generated file. Better Auth uses `text` type for IDs (not UUID). Match `user_files.user_id` type accordingly.

### 3. Create user_files schema

Create `backend/src/db/schema.ts`:

```typescript
import { pgTable, text, varchar, jsonb, uuid, timestamp, uniqueIndex, index } from "drizzle-orm/pg-core";
import { user } from "./auth-schema"; // Import Better Auth user table

export const userFiles = pgTable(
  "user_files",
  {
    id: uuid("id").defaultRandom().primaryKey(),
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    filename: varchar("filename", { length: 255 }).notNull(),
    entityType: varchar("entity_type", { length: 20 }).notNull(), // 'collection' | 'environment'
    content: jsonb("content").notNull(),
    updatedAt: timestamp("updated_at", { withTimezone: true }).notNull().defaultNow(),
    createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
  },
  (table) => [
    uniqueIndex("user_files_user_filename_idx").on(table.userId, table.filename),
    index("user_files_user_id_idx").on(table.userId),
    index("user_files_user_entity_idx").on(table.userId, table.entityType),
  ]
);

// Re-export auth schema for drizzle-kit
export { user, session, account, verification } from "./auth-schema";
```

### 4. Update drizzle.config.ts

Ensure schema points to both files:

```typescript
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  schema: ["./src/db/auth-schema.ts", "./src/db/schema.ts"],
  out: "./drizzle",
  dialect: "postgresql",
  dbCredentials: {
    url: process.env.DATABASE_URL!,
  },
});
```

### 5. Generate and apply migrations

```bash
cd backend
pnpm db:generate   # Creates migration SQL in drizzle/
pnpm db:migrate    # Applies to PostgreSQL
```

### 6. Update db/client.ts with schema

```typescript
import { drizzle } from "drizzle-orm/postgres-js";
import postgres from "postgres";
import { env } from "../env";
import * as authSchema from "./auth-schema";
import * as schema from "./schema";

const client = postgres(env.DATABASE_URL);
export const db = drizzle(client, {
  schema: { ...authSchema, ...schema },
});
```

### 7. Verify tables exist

```bash
psql -U localman -d localman -c "\dt"
# Should show: user, session, account, verification, user_files
```

### 8. Test auth endpoints

```bash
# Register a user
curl -X POST http://localhost:3001/api/auth/sign-up/email \
  -H "Content-Type: application/json" \
  -d '{"email":"test@test.com","password":"testtest123","name":"Test"}'

# Login
curl -X POST http://localhost:3001/api/auth/sign-in/email \
  -H "Content-Type: application/json" \
  -d '{"email":"test@test.com","password":"testtest123"}'
# Should return JWT token in response
```

## Risk Assessment

| Risk | Severity | Mitigation |
|---|---|---|
| Better Auth schema gen output changes | Medium | Pin version, review generated file |
| Drizzle migration conflicts | Low | Fresh DB for dev; migrations are additive |
| Better Auth user.id type mismatch | Medium | Check generated schema before referencing |

## Security Considerations

- Database user should have minimal privileges (not superuser)
- `user_files.content` is opaque jsonb — server never trusts client data structure
- CASCADE delete ensures no orphaned files when user deleted
- Password hashing handled by Better Auth (bcrypt by default)
