# Brainstorm: Localman Next Features Roadmap
**Date:** 2026-03-08 | **Status:** Complete

## Problem Statement
MVP Phase 1 (11 phases) hoàn thành. Cần xác định hướng phát triển tiếp theo cho Localman desktop API client.

## Context & Decisions

| Question | Decision |
|---|---|
| Mục tiêu chính | Phase 2: Web App (PWA) |
| Target user | Dev teams (2-20 người) |
| Backend | Chưa có, cần build |
| CORS strategy cho PWA | Tauri desktop app = local companion (WebSocket) |
| Backend stack | Node.js + Fastify |

## Recommended Architecture

```
[Desktop App (Done)] ──companion──► [PWA]
        │
        ▼
[Backend Server: Fastify + PostgreSQL]
        │
        ├── Auth (JWT)
        ├── Sync API (LWW)
        └── Team/Workspace API
```

## Phase Roadmap

### Phase A: Backend Server (Prerequisite — làm trước)
- Node.js + Fastify + PostgreSQL + Redis
- Auth: JWT access + refresh (client logic đã có)
- Sync API: POST /sync, GET /sync/pull (LWW đã implement client-side)
- PostgreSQL schema: users, workspaces, members, collections, requests, environments, sync_events
- Docker compose cho development

### Phase B: PWA
- Tauri app expose WebSocket server (localhost:14440) → companion
- PWA detect companion → route requests through Tauri (no CORS)
- Fallback: backend proxy nếu Tauri không chạy
- Service Worker + offline IndexedDB sync
- Share ~90% React codebase

**Security cho companion WS:**
- Origin validation + one-time token handshake
- Token generated by Tauri per session, stored in IndexedDB

### Phase C: Team Collaboration (Monetization play)
- Workspaces (personal + team)
- RBAC: owner / editor / viewer (3 roles đủ cho 2-20 người)
- Invite via email (24h token TTL)
- LWW conflict resolution + notification (không silent overwrite)
- Shared collections + environments

## Evaluated Approaches

### CORS Solutions (PWA)
| Approach | Verdict |
|---|---|
| Tauri as companion ✅ | Elegant, no extra install, reuse existing app |
| Separate agent binary | Overhead, extra artifact |
| Chrome Extension | Chromium-only, skip |
| Accept CORS limitation | Bad UX, skip |

### Conflict Resolution
| Approach | Verdict |
|---|---|
| Silent LWW | Loses changes without notification ❌ |
| LWW + Notification ✅ | Simple + transparent |
| 3-way merge | Over-engineering, skip ❌ |

## Implementation Sequence
